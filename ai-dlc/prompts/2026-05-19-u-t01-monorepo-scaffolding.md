## 2026-05-19 — Post-execution structural decision (recorded for honesty, not part of U-T01 prompts)

After U-T01 closed as `Done`, the human reviewer (Asitha) raised a structural observation:

> *"CabinConnect root is crowded. The actual product needs to go into a sub dir with a meaningful name — built as a monorepo with infra, data-layer, backend, frontend."*

This is a TFD-level decision (process / product folder separation) that should have been settled in TFD §3 *before* Bolt 0 began. The original TFD v0.1 missed it.

### What changed

| Before (U-T01 Construction loop output) | After (post-execution restructure) |
|---|---|
| `pnpm-workspace.yaml` at repo root | `platform/pnpm-workspace.yaml` |
| `apps/api/` | `platform/backend/` |
| `apps/web/` | `platform/frontend/` |
| `packages/shared-types/` | `platform/shared/` |
| `infra/` | `platform/infra/` |
| (no data-layer slot) | **`platform/data-layer/` (new peer)** |
| Root `README.md` had the Quickstart inline | Root `README.md` is a thin pointer; Quickstart lives in `platform/README.md` |

### Why this was an *adjustment to a Done Unit*, not a new Unit

This was a structural correction of the same scope already in U-T01 — moving the workspace shape, not adding new functionality. It was not safe to recompute U-T01's ACs because some of them referenced the original paths verbatim; the U-T01 ACs were rewritten to match the new shape (the *intent* of each AC was preserved). TFD §3, ADR-003 (v2), and the Change Log v0.2 entry capture the architectural change.

### Improvement candidate (for Bolt 0 retro)

**Process gap:** TFD §3 Repo Shape did not consider *process-vs-product folder separation* in its v0.1 draft. The Technical Foundation Review (TFR) ritual should ask explicitly: *"is the product code visually and structurally distinguishable from the process scaffolding at the repo root?"* — and demand a `Yes` with reasoning before signing off the TFD.

This is more than a CabinConnect-specific issue. It's a 99x AI-DLC adoption-level lesson. Should be added to the TFR checklist on `main`.
