## Notes and Findings

- **EC-011 (Booking.Nights year boundary)** was a false alarm from the archaeology. `DateOnly.DayNumber` is an absolute epoch-based day count, not `DayOfYear`. The existing implementation `CheckOut.DayNumber - CheckIn.DayNumber` is correct. AC1 and AC2 were written as regression tests to protect this correct behaviour.
- **EC-012 (BaseRate hardcoded to 0)** — confirmed bug; fixed.
- **EC-013 (DbUpdateConcurrencyException unhandled)** — confirmed bug; `DbUpdateConcurrencyException` is a subtype of `DbUpdateException`, so it must be caught first or it would be swallowed by the `when`-filtered `DbUpdateException` catch and bubble up as a 500.
- Adding `BaseRate` to `CreateCabinRequest` is a breaking API change — any existing client calling `POST /api/cabins` without `BaseRate` will get a 400. Flagged as a known contract change (no integration tests existed for this endpoint before this session).
