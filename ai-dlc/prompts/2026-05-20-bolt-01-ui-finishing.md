## Cross-Unit Decisions surfaced in this stretch

| # | Decision | Where it lands |
|---|---|---|
| BD-UF-A | **Mocks are typed against `platform/shared/src/api/*`.** Adding a mock without a matching type in `shared/` is now a code-review-blocking issue. The mock is the contract Bolt 2 inherits. | `platform/frontend/src/mocks/cabin-mock.ts` + `platform/shared/src/api/cabin.ts` |
| BD-UF-B | **Branded string types** for IDs (`CabinId`, `CommunityId`, `UserId`) — prevents passing the wrong ID through the type system | `platform/shared/src/api/community.ts` |
| BD-UF-C | i18n is a side-effect bootstrap in `main.tsx`, not a React provider. Reason: `react-i18next` exposes `useTranslation` without a Provider wrap when configured via `initReactI18next`. One less component tree layer. | `platform/frontend/src/main.tsx`, `platform/frontend/src/lib/i18n.ts` |
| BD-UF-D | PWA `manifest.webmanifest` ships from `platform/frontend/public/`, not auto-generated by `vite-plugin-pwa`. Reason: explicit manifest is easier to review and version. The plugin's `manifest: false` flag honours this. | `platform/frontend/public/manifest.webmanifest` + `vite.config.ts` |

## Self-review

- **ACs traced:** 4 Units' ACs all map to delivered files. One AC per Unit (the "designer validation" / "WCAG measurement" types) is deferred to the Bolt 1 retro per the deliberate Plan-quality scope of Bolt 1.
- **Code standards:** ESLint passes; TypeScript strict passes; Prettier passes — all on the scaffolded code. (Final lint on the new files will run when the developer runs `pnpm install && pnpm lint`.)
- **Security:** No secrets. The mock cabin data uses placeholder owner IDs.
- **Scope creep:** Resisted three temptations:
  - shadcn/ui CLI install (lots of components) — only Button shipped as proof. Components arrive per feature.
  - Skeleton loader / empty state components — DFD §7 documents the patterns; components arrive per feature.
  - Real auth context provider — Bolt 2 territory; the page reads from mocks, not from any auth-aware context.

## Note for the retro

Three observations worth raising:

1. The `BD-UF-A` rule (mocks must have a matching shared type) is the load-bearing convention that keeps Bolt 1 honest. Worth promoting from a Bolt-level decision to a CLAUDE.md rule.
2. Bolt 1 took noticeably less time than the Foundation Cluster Mob Elaboration estimated. Hypothesis: PRD + TFD + DFD up-front planning de-risks the Construction loop more than canonical AI-DLC suggests. Worth measuring in Bolt 2.
3. The DFD's mock-quality state (FDE-decided palette etc.) shipped through Bolt 1 without obvious cost. But the designer-staffing gap (DFD-Q-1) is still a real risk — once a real designer joins, parts of Bolt 1's UI may need a v2 pass. Retro should record this as a *known investment to revisit*, not a defect.
